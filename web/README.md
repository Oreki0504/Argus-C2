# Argus Console frontend

React + TypeScript + Vite, TanStack Query, React Router, Zod, static CSS and locally bundled Geist. Initial direction: Argus Hybrid (Geist hierarchy + Carbon shell/table patterns).

The UI supports the real Go HTTPS Console and a separate **development preview**. OIDC, browser sessions, Web roles and all four management APIs are implemented. Live mode uses same-origin Console routes and never falls back to fixtures or CLI Bearer APIs. See [HTTPS/Google/Auth0 setup](../docs/console.md), [Agent installation](../docs/agent-installation.zh-CN.md), [status](../docs/web-design.md) and [API contract](../docs/console-api.md). Periodic traffic telemetry remains future work.

## Preview

Use Node **24.22.2** (`.node-version`) and npm:

```sh
cd web
npm ci --ignore-scripts
npm run dev:mock
```

Open <http://127.0.0.1:5173>. The **Design preview** toolbar selects Admin/User, setup, sign-in, empty fleet, 300-node fleet, expired session, denial, 503, OIDC error and unavailable-capability scenarios. Default is anonymous User (guest); no sign-in is needed to view public summaries. Data/sign-in are simulated in memory; reload resets them. Keep `?scenario=user` (or another scenario) in the URL to retain that selection on reload. Never enter real secrets. Setup accepts any 64-character hex string, an HTTPS example issuer and a nonempty example Client ID.

For review from another machine on your LAN, run `npm run dev:lan` and open `http://<this-machine-LAN-IP>:5173`. This binds the mock preview to `0.0.0.0`. Plain HTTP LAN origins cannot register Service Workers, so the same MSW handlers resolve in browser memory instead. State stays local to each tab; production builds still exclude all mocks.

Overview uses clickable Agent cards with five aligned utilization meters. Anonymous and signed-in User pages have no sidebar; Log in sits at the top right for visitors. Admin uses the same full-width shell with Overview/Traffic/Management links in the header. Management has horizontal Tasks/Agents/Audit/Users & access navigation. Search and the five status filter cards share one horizontal row. Agent details include five sampled utilization charts, 1h/24h/7d ranges, keyboard/pointer inspection and a sample table. Anonymous reads use separate public endpoints and cache keys; no fake Web account is created. Overview, Fleet, server details and Traffic use allowlisted public DTOs. Management supports fixed collector tasks/results, enrollment tokens, exact-ID disable confirmation, audit filters, pending-user approval, role/access changes and session revocation. Agent details link directly to task creation. Lists have manual Refresh and cursor pagination. Mock workflows modify only per-tab memory; token creation does not invent an enrolled Agent. Live management uses the Go services. Public-name editing remains future work.

The [ARGUS UI standard](../docs/ui-design-system.md) prioritizes Overview and Details fitting a desktop viewport (1366×768 / 1440×900). Cards use adaptive pagination; Details groups five charts and system facts in two rows, with the sample table in a keyboard-accessible dialog. Small screens and zoom retain normal scrolling. Circular header controls switch Chinese/English and light/dark themes; only these display preferences persist locally. The login action uses quiet gray text without a rectangular border.

Add agent defaults to a one-command Linux/systemd installer with curl/wget choices and a manual enrollment fallback. Production requires operator-published static Agent binaries and a reachable Fleet origin; downloads are served by Console, with no GitHub Release dependency. Single-use installation links expire in 1–60 minutes and stay out of browser storage. Preview commands use a non-routable `.invalid` domain and cannot install an Agent.

`npm run dev` disables mocks and expects same-origin Console routes; without a backend on that origin it displays an error. For live use, build and serve the embedded UI from the HTTPS Go Console. There is no live-to-mock fallback, Bearer login, unsafe proxy or disabled certificate validation. The worker is served only in mock mode; production contains no worker or fixtures. Do not expose Vite as a management server.

## Validate and build

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit
```

Browser tests start mock and production-preview servers on 5173/4173; keep those ports free. They exercise UI interactions with simulated responses; Go tests separately exercise signed TLS OIDC exchanges and real management transactions. Axe checks supplement manual accessibility review. Unit tests cover missing data, transport/redaction, strict DTOs, management guards, principal/role cache scoping and cancellation. CI supplies `ARGUS_CONSOLE_CONTRACT_FILE`, generated by the Go integration test, to validate actual response schemas across languages.

The opt-in `TestConsoleBrowserHarness` and `tests/live-console.spec.ts` additionally exercise the actual HTTPS Go server using ephemeral test TLS and a signed test IdP: setup, redirects/cookies, writes/audit, single-use installer redemption, artifact checksum validation, logout and login. Set `ARGUS_CONSOLE_BROWSER_INFO` to a private temporary file for both processes. Optionally set `ARGUS_CONSOLE_TEST_ARTIFACTS` on the Go harness to a directory built by `deploy/linux/build-agent-artifacts.sh` to validate real Agent binaries. Downloads are never executed by the browser test. Without the info-file variable the live browser test is skipped; production has no test authentication route.

Build output goes to ignored `../internal/webui/dist`. Then:

```sh
cd ..
go test -tags ui ./internal/webui
go build -tags ui ./...
```

Normal Go build/test requires no Node. `internal/webui.Handler()` is mounted only on the optional independent HTTPS Console listener. `-tags ui` includes assets but does not enable that listener; supply the four Console flags. The Go handler provides production CSP; Vite uses development HMR behavior.

The nested `web/go.mod` only excludes npm packages containing Go examples from the server's `go test ./...` traversal. It contains no backend code. For environments with a separately staged Chromium binary, `ARGUS_CHROMIUM_PATH` may point Playwright to that executable; normal development/CI uses the Playwright-managed browser.

## Source layout

- `src/api`: Console DTOs, validators, cookie/CSRF transport, safe errors and query scoping.
- `src/features/auth`, `setup`: session restoration, login/logout and first-run wizard.
- `src/features/fleet`, `nodes`, `traffic`: public summaries and observation semantics.
- `src/features/management`: Tasks, Agents, Audit, Users & access, guards and dialogs.
- `src/components`, `src/styles.css`: semantic primitives and design tokens.
- `src/mocks`: development-only MSW fixtures and review controls.
- `tests`: interaction, responsive/accessibility and production-isolation checks.

Dependencies are pinned with a lockfile. `minimatch` is overridden to 11.0.1 for GHSA-g3hv-75wg-m249 in the lint toolchain; remove after upstream ranges include the fix and rerun lint/audit. Font/icon licenses remain in their upstream packages.
